# TaskPilot AI — 你的私人本地任务小助手

## 这是什么？

把它想象成一个**超级懒人模式**的项目管理员。你告诉它想干什么，它就帮你干——读文件、跑测试、分析结果，最后甚至还帮你写个报告。

**官方说法**：一个本地轻量级 Web Agent 演示：用户输入任务，系统执行规则分析流程（读取文件 → 运行 pytest → 分析结果），将步骤/结果持久化到 SQLite，并生成最终报告。

**我觉得**：打开网页，在框里输个“我想让你读读这个文件并跑一下测试”，点个按钮，它就开始忙碌了。你可以看到它每一步在干嘛，最后它还会给你一个漂亮的结语。全程记录在案，不会丢。

## 🏗️ 它到底能干嘛？

简单来说，三步走：

1. **规划**：读懂你的任务，拆解成几个小步骤
2. **执行**：
   - 读相关文件（read_file）
   - 跑 pytest 测试（pytest_runner）
   - 用 ReportAnalyzerTool 分析测试输出
3. **交付**：生成最终报告，把所有步骤和工具调用都记录在 SQLite 数据库里

### 举个例子

你输入：`读读 demo_project_a/README.md 了解测试说明，然后在里面跑 pytest -v，最后分析一下结果`

Agent 会：
- ✅ 第一步：打开 README.md，把内容读进来
- ✅ 第二步：在 demo_project_a 目录下跑 `pytest -v`
- ✅ 第三步：把测试输出喂给分析器，生成结论
- ✅ 第四步：把整个过程记在数据库，并给你一个 final_report

## 🚀 怎么运行？

```bash
# 1. 克隆或下载项目
git clone ... # 或者直接下载代码

# 2. 安装依赖
cd taskpilot
pip install -r ../requirements.txt

# 3. 启动服务
python run.py
```

启动后，打开浏览器访问 `http://localhost:8000`，你就看到一个简简单单的输入框了。

## 📦 项目结构（大概）

```
taskpilot/          # 主要代码
├── main.py         # 核心逻辑，Agent 的大脑
├── db.py           # SQLite 数据库连接（已修复线程问题）
├── config.py       # 配置文件，包括 DB 路径
├── tools/          # 各种工具模块
│   ├── pytest_runner.py  # 负责跑测试
│   ├── file_reader.py    # 负责读取文件
│   └── report_analyzer.py # 负责分析生成报告
└── schemas.py      # 数据结构定义

frontend/           # 前端界面
├── index.html      # 页面结构（已修复中文乱码）
├── app.js          # 交互逻辑（有超时、错误处理等）
└── style.css       # 样式（加了 toast 动画）

demo_projects/      # 演示用的测试项目
run.py              # 启动入口
README.md          # 你看到的这份文档
```

## 🛡️ 已知限制
- 数据库是本地的，关闭网页数据就没了（除非你手动查 SQLite 文件）
- 并发（多人同时用）还没测试过，建议单人单任务模式
- 超过一定复杂度的任务可能会有点慢（每步都要等前一步 finish）
